# Install Bee

Bee is a single executable. Prebuilt binaries are published on the [releases page](https://github.com/tokhive/bee/releases) for macOS and Linux, on `amd64` and `arm64`.

## Install script (recommended)

```sh
curl -fsSL https://raw.githubusercontent.com/tokhive/bee/main/install.sh | sh
```

The script picks the build for your operating system and CPU, verifies it against the release's `checksums.txt` and installs `bee` to `~/.local/bin`.

On Linux, it also registers and enables the system-level `tokhive-bee` service, so Bee starts after a reboot without anyone logging in over SSH. Run the installer as the user who will pair Bee; do not put the whole command under `sudo`. Only service management requests administrator access.

In an interactive terminal, first choose **简体中文 / English**. After installing the program, the installer asks **Set up and start Bee now?** (default yes). Sign in to your official clients first (`codex login` or `claude`), then follow the three setup steps:

1. Enter your Hive address and confirm the pairing link in Hive's web console. An existing device configuration is validated or its unfinished pairing resumed.
2. Choose which signed-in accounts to supply. Existing account configuration is kept, so you do not have to choose again.
3. The installer starts the background service and checks that systemd reports it as active. Use `bee status` to check Hive connectivity and whether accounts can take work.

If Hive has deleted or replaced this device and rejects its previous pairing, the interactive installer offers to pair again (default **no**). After you agree and enter the Hive address, it stops the service, backs up only `bee.json` into a private, uniquely named directory beside it, and shows the backup path. It then opens the normal web pairing flow and reuses `egress.json`. Re-pairing requires the Linux `flock` tool (usually included in `util-linux`); a busy configuration lock or a changed configuration stops recovery. Declining or ending input keeps the existing configuration. A failed new pairing keeps both the backup and any newly saved pairing state so you can resume by running the installer again. Confirming a replacement in Hive may deactivate another Bee.

The steps are labeled **1/3 device pairing**, **2/3 supplied accounts**, and **3/3 background startup**. Existing configuration reduces the questions you need to answer, while the completed flow still reaches step 3/3 and shows the final service state. Separators, icons and colors make each stage visible. Redirected output or `TERM=dumb` uses plain text; `NO_COLOR=1` disables colors.

Set `BEE_LANG=zh` or `BEE_LANG=en` to skip the language menu. Without a terminal, the default follows the first nonempty `LC_ALL`, `LC_MESSAGES`, or `LANG`: `zh` locales use Chinese, all others use English. `bee login` and `bee setup` also recognize `BEE_LANG`. Full bilingual pairing and account selection require a Bee release containing this support; older releases retain their original command output. The choice applies to the current installation and is not stored in the service configuration.

You can decline or set `BEE_INSTALL_INTERACTIVE=0`. Without an interactive terminal, the wizard is skipped automatically. Automatic startup is still enabled, and the installer prints manual commands with your actual paths. With the default configuration paths:

```sh
bee login --hive https://hive.example.com  # existing pairing: bee login
bee setup                              # only if egress.json is missing
sudo systemctl start tokhive-bee
sudo systemctl status tokhive-bee
sudo journalctl -u tokhive-bee -f
```

If a step fails, the wizard stops and preserves the installed binary and any configuration already written; follow the original error and retry or use the manual commands. If a foreground Bee holds the same configuration, stop it first. The service runs as the installing user and skips startup until both pairing and account configuration files exist. Linux service installation requires a running systemd manager (version 243 or newer for configuration checks) and administrator access. macOS installation remains binary-only; follow [first-run setup](./first-run.mdx).

| Variable | Effect |
| --- | --- |
| `BEE_VERSION` | Install a specific release, for example `BEE_VERSION=v0.1.0`. Defaults to the latest release. |
| `BEE_INSTALL_DIR` | Install somewhere other than `~/.local/bin`. |
| `BEE_INSTALL_SERVICE` | Linux defaults to `1`, enabling the system service. Set `0` for binary-only installation, including systems without systemd or administrator access. |
| `BEE_INSTALL_INTERACTIVE` | Defaults to `1`. Set `0` to skip setup/start prompts, for example in unattended installation. |
| `BEE_LANG` | Set `zh` for Simplified Chinese or `en` for English and skip the language menu. |
| `NO_COLOR` | Set to a nonempty value to disable terminal colors. |

For example:

```sh
curl -fsSL https://raw.githubusercontent.com/tokhive/bee/main/install.sh | BEE_VERSION=v0.1.0 sh
```

To install only the binary:

```sh
curl -fsSL https://raw.githubusercontent.com/tokhive/bee/main/install.sh | BEE_INSTALL_SERVICE=0 sh
```

To enable the Linux service without entering the wizard:

```sh
curl -fsSL https://raw.githubusercontent.com/tokhive/bee/main/install.sh | BEE_INSTALL_INTERACTIVE=0 sh
```

To use Chinese without the language menu:

```sh
curl -fsSL https://raw.githubusercontent.com/tokhive/bee/main/install.sh | BEE_LANG=zh sh
```

The service records the installation's binary path, home, configuration directory, executable search path and official-client directory variables. Use the same environment when installing and pairing. Use `sudo systemctl edit tokhive-bee` for other required environment variables or non-default device/egress paths. Credentials must be accessible without an interactive login; starting a service does not unlock a login-locked keyring.

If you used the old user-level service, first run `systemctl --user disable --now tokhive-bee`. The installer refuses to overwrite a hand-written or linked system unit; use `BEE_INSTALL_SERVICE=0` to keep that service, or migrate it explicitly.

If `~/.local/bin` is not on your `PATH`, add it to your shell profile, or call Bee by its full path.

Check the installation:

```sh
bee version
```

## Manual download

1. Download `bee_<os>_<arch>.tar.gz` for your machine and `checksums.txt` from the [releases page](https://github.com/tokhive/bee/releases). `<os>` is `darwin` or `linux`, `<arch>` is `amd64` or `arm64`.
2. Verify the archive:

   ```sh
   shasum -a 256 -c checksums.txt --ignore-missing
   ```

3. Extract it and move `bee` onto your `PATH`:

   ```sh
   tar -xzf bee_linux_amd64.tar.gz
   mv bee ~/.local/bin/
   ```

:::note[macOS: "cannot be opened" or "developer cannot be verified"]
A file downloaded through a browser is quarantined, and Gatekeeper refuses to run the unsigned binary. Clear the flag:

```sh
xattr -d com.apple.quarantine bee
```

The install script downloads with `curl` and is not affected.
:::

## Build from source

You need Go 1.27.3 or newer, plus `git` and `bash`.

```sh
git clone https://github.com/tokhive/bee.git
cd bee
make build        # builds bin/bee
```

Bee depends on the TEE client library `github.com/tokhive/tee` as an ordinary Go module pinned in `go.mod`. You can also build with `go build -o bin/bee ./cmd/bee`.

Put `bin/bee` on your `PATH`, or call it as `./bin/bee`. A source build reports its version as `dev`, followed by the commit when built inside the repository, for example `dev+3f82e19a1b2c`.

## Manage Bee from the terminal

Run `bee` without arguments in a terminal:

```sh
bee
```

Choose **简体中文 / English**, then enter a number to view status, pair or re-pair the device, manage supplied accounts, control the background service, or read logs and diagnostics. Account management includes selecting official sign-ins, pausing/resuming new work, and confirming a changed account. Use `0` to return directly from a submenu, or to exit from the main menu. Exiting the menu leaves the background service running.

`BEE_LANG=zh` or `BEE_LANG=en` skips the initial language question. Language can also be changed inside the menu and only affects that session. Confirmations use **1) Confirm / 0) Cancel**, with cancellation as the default. Known errors and recovery steps follow the selected language. HTTP statuses and error codes stay visible; unfamiliar external errors and service logs are labeled as original technical details. Compact pages use status icons and colors; `NO_COLOR=1` disables colors, and `TERM=dumb` uses plain text.

Linux service controls apply only to the installer's system service for the same user, executable and configuration. Custom units, drop-ins, or a different binary/configuration path require manual management. **Start/stop** controls Bee now; **enable/disable boot startup** controls the next reboot. Saving account choices is separate from applying them: a running service loads the changes only after you confirm a restart. The status view distinguishes service activity, account authorization and readiness to take work.

The other menu actions work on macOS; background service controls are unavailable there, so use `bee start` for foreground operation. All existing subcommands remain available. Bare `bee` prints help without waiting for input when either input or output is not a terminal.

The menu requires a new Bee binary containing this feature. Updating `install.sh` alone does not add it to an older release. Before release, build the menu branch with `make build` and run `./bin/bee`.

## Upgrade

Run the install script again. It replaces `bee` in place and updates its managed Linux service. If the service is active, the wizard asks whether to restart it; the default is **no**, preserving current work. It does not repeat pairing or account selection. A service in a transitional state is left in place. Without a terminal or with the wizard disabled, no restart is attempted. When current work can be interrupted, apply the upgrade with `sudo systemctl restart tokhive-bee`. For a foreground process, stop it with Ctrl-C and run `bee start` again.

Bee tells Hive which version is connecting, and the console shows it on the **Bee Device** page, so you can check that the upgrade took effect.

## Uninstall

1. Stop Bee. If using the installed Linux service, disable and remove it first:

   ```sh
   sudo systemctl disable --now tokhive-bee
   sudo rm /etc/systemd/system/tokhive-bee.service
   sudo systemctl daemon-reload
   ```

2. Delete the binary, for example `rm ~/.local/bin/bee`.
3. Optionally delete Bee's configuration directory (see [Configuration](./configuration.mdx#device-configuration)). This removes the device pairing; the machine has to be paired again to supply.

Bee never signs you out of the official clients, so Codex and Claude Code keep working as before.
