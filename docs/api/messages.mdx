# Messages

```http
POST /anthropic/v1/messages
x-api-key: <your key>
anthropic-version: 2023-06-01
Content-Type: application/json
```

Anthropic's native Messages API, served by Claude subscriptions. TokHive does not convert it: request and response are Anthropic's own format, streaming and non-streaming. Official SDKs and Claude Code work by pointing their base URL at `https://api.tokhive.ai/anthropic`.

```sh
curl https://api.tokhive.ai/anthropic/v1/messages \
  -H "x-api-key: $TOKHIVE_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{"model":"claude-opus-5-5","max_tokens":64,"messages":[{"role":"user","content":"Reply with exactly OK."}]}'
```

```python
import anthropic

client = anthropic.Anthropic(base_url="https://api.tokhive.ai/anthropic", api_key=TOKHIVE_API_KEY)
message = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=64,
    messages=[{"role": "user", "content": "Reply with exactly OK."}],
)
```

For Claude Code, set `ANTHROPIC_BASE_URL` to `https://api.tokhive.ai/anthropic` and `ANTHROPIC_AUTH_TOKEN` to your key, as in the [Quickstart](../quickstart.mdx).

## Request

- `model`, a positive `max_tokens` and a non-empty `messages` are required. `anthropic-version` must be `2023-06-01`.
- Other fields, such as `system`, `tools`, `thinking`, `metadata`, `output_config`, `temperature` and `context_management`, are passed through unchanged, as are `anthropic-beta` features.
- In a stream, the final `message_stop` event is held back until the result is verified and settled. A non-streaming response is likewise returned only after verification.

## Fast mode is not offered

TokHive serves every Messages request at the **standard speed**. A request that asks for fast mode (`"speed": "fast"`, or any value other than `"standard"`) is quietly changed to `"speed": "standard"` before it is sent. It runs at the standard speed and is billed at the standard price. There is no error and no extra marker in the response. A request without `speed` is sent as it is.

This is because, on a Claude subscription, fast mode does not use the plan's quota. It is billed from the first token to the provider's prepaid extra usage, at the API's premium price, which TokHive does not price. If your client has fast mode switched on, for example with `/fast` in Claude Code, it keeps working, just at the standard speed.

## Usage and billing

Claude's `input_tokens` counts uncached input only. TokHive bills each kind of token at its own price:

| Usage field | Billed as |
| --- | --- |
| `input_tokens` | Input |
| `cache_read_input_tokens` | Cache read |
| `cache_creation.ephemeral_5m_input_tokens` | 5-minute cache write |
| `cache_creation.ephemeral_1h_input_tokens` | 1-hour cache write |
| `output_tokens` | Output |

## Conversations

A conversation keeps to the provider account that served it, which keeps the upstream prompt cache warm. TokHive recognizes the conversation from the `x-claude-code-session-id` header or from the session in `metadata.user_id`. If both are present, they must agree. Session identifiers are replaced with a digest scoped to you before they reach the upstream.

Plain text, client tool calls and their results, and inline base64 images can continue on another account when the original one is unavailable. Thinking signatures, file references, remote image URLs, containers and unknown content blocks only make sense on the original account. If that account is unavailable, such a call returns `409 session_context_unavailable`. With a `Retry-After` header, the same history can continue later. Without one, start a new conversation.

## Token counting

```http
POST /anthropic/v1/messages/count_tokens
```

Returns `{"input_tokens": N}` as counted by the upstream itself, because Anthropic does not publish the tokenizer of current models. The body is the same as for Messages, but without `stream` and `max_tokens` is not required.

- **Free.** Counting is never charged, but it does need a positive balance and counts toward your key's concurrency limit.
- Counting does not affect which account later Messages calls use.
- When the upstream rejects the request (`400`, `413` or `422`), its error is passed through. Other failures return `502`.
